# 도착 알림 기획 (포그라운드 서비스)

작성일: 2026-09-09
상태: 기획 확정 · UI 작업 중

## 1. 목적

사용자가 앱을 확인했더니 버스가 30분 뒤에 온다. 앱을 계속 켜놓고 볼 수 없으니,
"도착 알림"을 켜두면 앱이 꺼져 있어도 버스가 오기 전에 알려주고, 버스가 오고 나면 스스로 꺼진다.

## 2. 사용자 경험

1. 메인 화면(도착 정보)에서 "도착 알림" 버튼을 켠다. 앱이 떠 있는 상태에서만 켤 수 있다.
2. 상단 알림 영역에 지울 수 없는 알림이 뜨고 "51번 버스 · 12분 후 도착"처럼 분 단위로 갱신된다.
3. 도착 **10분 · 5분 · 3분 · 1분 전**, 총 4번 소리·진동 알림이 울린다.
4. 예상 도착 시각이 지나면 알림이 사라지고 기능이 자동으로 꺼진다. "지나갔습니다" 같은 사후 알림은 없다.
   이 알림을 보고 타려는 사람은 이미 정류장에 있으므로 의미가 없다.
5. 상단 알림의 "끄기" 버튼이나 앱의 버튼으로 언제든 직접 끌 수 있다.

## 3. 확정된 규칙

### 알람 4회

- 알람은 API 조회 시점이 아니라 **서비스 안의 1초 카운트다운 기준**으로 울린다. 메인 화면과 같은 방식이다.
  조회는 카운트다운을 보정하는 용도라 조회 주기와 상관없이 정확한 시점에 울린다.
- 활성화 시점 남은 시간보다 큰 시점은 처음부터 제외한다. 남은 시간이 7분이면 5·3·1분만 울린다.
- 보정으로 시간이 확 줄어 두 시점을 한 번에 지나치면(6분 → 2분 30초) 가장 가까운 3분 알람 하나만 울린다.
- 보정으로 시간이 다시 늘어나도 이미 울린 시점은 다시 울리지 않는다.
- 남은 시간이 1분 미만이면 울릴 알람이 없으므로 버튼을 비활성화한다.

### 종료 조건 (두 가지뿐)

1. **카운트다운이 0 이 되면 종료.** API 를 보지 않는다.
2. **조회 결과의 첫 버스 차량번호(`plateNo1`)가 활성화 때 기억한 것과 다르면 종료.**
   버스가 예상보다 일찍 지나간 경우와 운행 종료로 버스가 사라진 경우를 문자열 비교 한 번으로 잡는다.

안전장치는 최대 추적 시간 90분 하나만 둔다. API 조회 실패는 무시하고 카운트다운을 이어간다.
추월 처리, 빈 값 폴백, 연속 실패 카운트는 넣지 않는다.

### 동시 추적

한 번에 한 건만. 다른 버스에서 켜면 기존 추적을 끄고 새로 시작한다.

### 조회 주기

| 남은 시간 | 조회 주기 |
|---|---|
| 10분 초과 | 120초 |
| 10분 이하 | 60초 |

30분 추적에 약 20회. 알람 타이밍은 카운트다운이 맡으므로 마지막 구간을 더 당기지 않는다.

### 앱을 보고 있을 때 중복 조회

추적 중에 메인 화면을 열면 화면의 60초 폴링과 서비스 폴링이 같은 정보를 따로 받는다.
화면을 보는 동안만 생기는 작은 낭비라 첫 버전은 그대로 둔다.
줄이고 싶으면 "추적 중인 버스 화면은 서비스가 받은 데이터를 받아 쓴다"로 바꾼다.

## 4. 권한

매니페스트 선언만으로 되는 것 (사용자 동의 불필요):

```xml
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_DATA_SYNC" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />

<service
    android:name="com.pravera.flutter_foreground_task.service.ForegroundService"
    android:foregroundServiceType="dataSync"
    android:exported="false" />
```

사용자에게 물어야 하는 것 — 안드로이드 버전에 따라 다르다. 어느 버전이든 마지막 질문은 하나,
"지금 이 앱이 알림을 띄울 수 있는가"이고, 아니오일 때만 공통 권한 다이얼로그가 뜬다.

| 버전 | 흐름 |
|---|---|
| Android 13 이상 (API 33+) | 알림 권한이 런타임 권한. 이미 허용이면 바로 켜짐. 아직 안 물어봤으면 시스템 팝업 요청 → 허용이면 켜짐, 거부면 공통 다이얼로그. 두 번 거부하면 시스템 팝업이 더 안 뜨므로 "설정 열기"가 유일한 경로 |
| Android 8 ~ 12 (API 26~32) | 런타임 권한 없음, 기본 허용. 사용자가 설정에서 이 앱 알림을 꺼둔 경우만 알림 사용 가능 여부 조회로 확인 → 꺼져 있으면 공통 다이얼로그 |
| 모든 버전 공통 | 알림 채널 두 개(고정 알림 무음 / 알람 소리·진동)는 앱 시작 시 미리 만든다. 사용자가 알람 채널만 꺼둔 경우도 "알림을 받을 수 없음"으로 보고 같은 다이얼로그. Android 14 이상은 서비스 종류 선언이 있어야 서비스가 시작된다 (매니페스트, 사용자 동작 없음) |

- 다이얼로그가 뜨면 버튼은 켜지 않는다. "설정 열기"는 이 앱의 알림 설정 화면으로 이동한다.
- minSdk 는 Flutter 기본값이라 실제 지원 하한을 구현 시 확인한다.

쓰지 않는 것:

- 배터리 최적화 제외 요청: Play 정책 제한 대상. 포그라운드 서비스는 이미 대부분의 절전 제한에서 제외된다.
- 정확한 알람 권한, 다른 앱 위에 표시 권한: 이 설계에 필요 없다. 알림 탭으로 앱 열기는 알림 자체의 PendingIntent 라 별도 권한이 없다.
- 서비스 종류 `remoteMessaging`: 해당 없음. `dataSync` 만 쓴다. Android 15 의 24시간 중 6시간 제한은 최대 90분 추적이라 문제없다.

## 5. 환경 확인 (2026-09-09)

- Flutter 3.44.4 / Dart 3.12.2, Kotlin 2.2.20, AGP 8.11.2, compileSdk·targetSdk 36
- `flutter_foreground_task` 11.0.3 요구사항(Flutter 3.44+, Dart 3.12+, Kotlin 2.2.20+, Gradle 8.11+) 전부 만족
- 도착 API 엔티티에 `plateNo1`/`plateNo2` 가 들어오지만 매퍼가 모델로 넘기지 않는다 → 모델에 추가 필요
- 메인 화면은 `AppLifecycleListener` 로 백그라운드 진입·복귀를 이미 처리한다 → 버튼 상태 동기화 지점

## 6. 구조

판정 로직은 플러그인에서 분리해 순수 Dart 로 두고 단위 테스트한다. 기존 뷰모델 테스트 방식(hand-written fake)을 쓴다.

| 파일 | 역할 | 테스트 |
|---|---|---|
| `model/bus_arrival_model.dart`, `mapper/bus_arrival_mapper.dart` | `plateNo1` 추가 | 매퍼 테스트 확장 |
| `tracking/bus_tracker.dart` | 순수 로직. 카운트다운, 4회 알람 시점 판정, 종료 판정, 다음 조회 주기, 알림 문구 | 단위 테스트 핵심 |
| `tracking/bus_tracking_task_handler.dart` | 서비스 isolate 진입점. Dio·API 서비스·Repository 를 직접 생성해 주기마다 조회하고 tracker 에 넘김. 알림 갱신, 자체 종료 | 얇게 유지, 실기기 검증 |
| `tracking/bus_tracking_service.dart` | UI 쪽 파사드. 권한 확인·시작·중지·실행 여부. GetIt 등록 | 인터페이스로 두고 테스트에서 fake |
| `viewmodel/bus_main_view_model.dart` | 알림 켜짐 상태와 `toggleAlarm()` | 기존 테스트 파일 확장 |
| `screen/main_screen/bus_main_screen.dart` | 히어로 아래 "도착 알림" 버튼, 권한 거부 안내 | 위젯 테스트 |
| `main.dart` | 패키지 초기화, 파사드 등록 | |

- 서비스 isolate 에는 GetIt·Provider 가 없다. 진입점에서 `DioSingleton` 으로 Dio 를 만들고
  `BusApiService`, `BusArrivalRepository` 를 직접 생성해 기존 파싱 코드를 재사용한다.
- 추적 대상 버스는 서비스 시작 전에 패키지의 `saveData` 로 저장해 두고 isolate 에서 읽는다.
- 알림은 두 개다. 상단 고정 카운트다운 알림은 패키지가 관리(무음 채널), 4회 알람은 `flutter_local_notifications` 로
  소리·진동 채널에 띄운다. 패키지는 알림 하나만 관리하고 갱신 때 울릴지를 세밀히 제어할 수 없다.
- 버튼 상태 동기화: 서비스가 스스로 꺼졌을 때 앱이 떠 있으면 서비스→앱 메시지로 즉시 반영하고,
  앱이 꺼져 있었으면 화면 복귀 시 `isRunningService` 와 저장된 추적 대상을 읽어 "이 버스를 추적 중인가"로 그린다.

## 7. UI 명세 (메인 화면)

- 위치: 히어로 카드 아래, "전체 노선 보기" 버튼과 같은 줄. 왼쪽 "도착 알림", 오른쪽 "전체 노선 보기".
- 꺼짐: tonal 버튼, 종 아이콘(`notifications_none`), 라벨 "도착 알림".
- 켜짐: primary 채움 버튼, 종 아이콘(`notifications_active`), 라벨 "알림 켜짐".
- 설명은 화면에 남기지 않고 토스트로만: 켤 때 "도착 10·5·3·1분 전에 알려드려요", 끌 때 "도착 알림을 껐어요".
  리스트 화면의 `_showSnackBar` 와 같은 모양(floating, margin 16, radius 12, 2초).
- 남은 시간 1분 미만이면 버튼 비활성화.
- 운행 없음·에러 화면에는 버튼이 없다.
- 안드로이드 알림은 제목 한 줄만: 알람 "51번 버스가 5분 후에 도착해요", 고정 알림 "51번 버스 · 5분 후 도착" + "끄기" 버튼.

### 공통 권한 다이얼로그 (`widget/app_permission_dialog.dart`)

아이콘·제목·설명·"설정 열기" 동작만 바꿔 앱 전체에서 재사용한다. 기존 삭제 확인 다이얼로그와 같은 16px 모서리,
아이콘+제목 행 구조를 따른다.

| 인스턴스 | 아이콘 | 제목 | 본문 | 버튼 |
|---|---|---|---|---|
| 알림 권한 (도착 알림) | 종 | 알림 권한이 필요해요 | 알림을 허용해야 버스가 오기 전에 알려드릴 수 있어요. 설정에서 "버스 언제와" 알림을 켜주세요. | 나중에 / 설정 열기 → 앱 알림 설정 화면 |
| 위치 권한 (정류장 찾기, 나중에 교체) | 핀 | 위치 권한이 필요해요 | 내 주변 정류장을 찾으려면 위치 권한이 필요해요. 허용하지 않으면 수원역 주변을 대신 보여드려요. | 기본 위치로 / 설정 열기 → 앱 정보 화면 |

지금 지도 화면은 안내 문구만 띄우고 있어 위치 권한 인스턴스는 이 작업 범위 밖이다. 위젯만 공통으로 만들어 두고 나중에 교체한다.

## 8. 작업 순서

1. 기획 문서 (이 파일) ✅
2. UI: 버튼·토스트·공통 권한 다이얼로그 위젯. 뷰모델은 켜짐/꺼짐 bool 만 가진다 → 위젯·뷰모델 테스트 ✅ (브랜치 `feature/arrival-alarm`, 실기기 확인 대기)
3. 모델·매퍼에 `plateNo1` 추가 → 매퍼 테스트
4. `BusTracker` 순수 로직 → 단위 테스트
   (활성화 시 건너뛰기, 보정으로 두 시점 동시 통과, 보정 후 시간 증가, 차량번호 변경, 0 도달, 90분)
5. `flutter_foreground_task` + `flutter_local_notifications` 추가, 매니페스트, `main.dart` 초기화, 파사드, TaskHandler
   → analyze 0건, 빌드 성공
6. 뷰모델을 파사드에 연결 + fake 파사드 테스트
7. 실기기: 앱 종료·잠금 상태에서 알람 4회 타이밍, 0 도달 시 자동 종료,
   `adb shell dumpsys deviceidle force-idle` 로 절전 모드 강제 진입 후 지속 여부
