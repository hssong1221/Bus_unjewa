## 1. 데이터 계층

### 꼭 고칠 것 (보류 중)

**1-1. 저장 데이터 하나만 못 읽어도 즐겨찾기 전체가 사라짐**

- 위치: `bus_51/lib/service/storage_service.dart` `loadUserModelList()`
- 현재: 리스트 전체를 한 번에 파싱하고, 실패하면 `[]` 를 반환한다 (출시 전 "구버전 데이터는 마이그레이션 없이 버린다" 결정).
- 문제: 실제 사용자가 생긴 지금은 다음 경우에 즐겨찾기 전부가 사라지고 스플래시가 온보딩으로 보낸다. 온보딩에서 새로 저장하면 원래 데이터를 덮어써서 복구도 불가.
  - 업데이트에서 `UserSaveModel` 에 `required` 필드를 추가 → 기존 데이터 전부 파싱 실패
  - 항목 하나만 깨져도 정상 항목까지 같이 버려짐
- 수정안:
  - 항목별로 파싱해서 깨진 항목만 건너뛴다
  - 테스트 2개: 깨진 항목이 섞인 데이터, 새 필드가 없는 옛 데이터

### 규칙: `UserSaveModel` 필드 변경

기기에 저장된 JSON 이라 업데이트 전 데이터가 그대로 남아 있다. 필드를 바꿀 때는 옛 데이터도 읽히게 한다.

- **추가**: `required` 금지. `@Default(...)` 를 주거나 nullable(`String?`)로 넣는다. 화면은 값이 비어 있으면 안 보여주는 식으로 처리한다.
- **삭제**: 괜찮다. 옛 데이터의 남은 키는 무시된다.
- **이름 변경**: 새 이름에 기본값이 없으면 추가와 같은 문제. `@JsonKey(name: '옛이름')` 으로 저장 키를 유지한다.

### 넘겨도 되는 것

- `deleteUserData()` 가 저장 완료를 기다리지 않음 (`bus_list_view_model.dart` `deleteAll`). 캐시엔 즉시 반영되므로 화면 문제는 없음.
- `loadUserModelList()` 가 저장 원문을 `debugPrint` 함. 릴리즈에선 꺼져 있음.

### 이상 없음

- API 응답 처리: resultCode 검사, 게이트웨이 오류, `@Default('')` + `SafeStringConverter`, ViewModel 의 일반 예외 catch.
- 노선 정류장 캐시(실패·빈 응답은 캐시 안 함), 정류장 반경 필터.

## 2. 상세 화면 + 도착 알림

### 꼭 고칠 것

없음.

### 넘겨도 되는 것

- **서비스 시작 직후 실패 시 "끄기"가 안 먹음**: `BusTrackingTaskHandler.onStart` 에서 알림 초기화나 대상 해석이 예외를 던지면 `_tracker` 가 null 인 채 고정 알림만 남고, `_finish()` 가 `_tracker == null` 이면 바로 돌아가서 알림의 "끄기"로 내릴 수 없다. 앱의 알림 버튼으로는 내릴 수 있고, 대상 JSON 은 앱이 방금 쓴 값이며 앱 업데이트 시 서비스는 재시작되지 않으므로(`autoRunOnMyPackageReplaced: false`) 사실상 일어나지 않는다.
- **도착 직후 다른 버스로 교체하는 1초 남짓한 틈**: 서비스가 끝나는 중에 다른 버스 알림을 켜면 버튼은 켜짐인데 서비스는 내려간 상태가 될 수 있다. 화면에 다시 들어오거나 앱 복귀 시 `_syncAlarmState` 가 꺼짐으로 맞춘다.
- 9/14 이월 항목 재판단: 즐겨찾기를 지워도 추적이 계속되는 건 의도된 동작으로 봐도 됨(알림은 도착·90분에 스스로 끝남). `allowAutoRestart` 기본 true 는 시스템 재시작 시 `TaskStarter.system` 에서 바로 재조회하므로 문제없음. 서비스 isolate 의 `debugPrint` 는 개인 정보가 없어 무해.

### 이상 없음

- 추적 판정(`BusTracker`): 알람 시점 제외·몰아서 지나친 경우 하나만 울리기·차량 변경 종료·90분 상한·조회 주기.
- 서비스 교체 경쟁 상태: stop→start 대신 `sendDataToTask` 로 교체, `_releaseTarget` 의 "아직 내 것인가" 확인, 응답 대기 중 교체 시 결과 버림.
- 화면: 백그라운드 시 갱신·카운트다운 정지, 복귀 시 재조회 + 알림 상태 동기화, 알림 버튼 연타 가드, 권한 거부 → 설정 열기.
- 알림 id 분리(고정 51 / 알람 5151), 알람 채널만 꺼 둔 경우도 권한 없음으로 처리.

## 4. 시작·온보딩

### 꼭 고칠 것

없음.

### 고치면 좋은 것 (작은 수정) — 2건 모두 수정 완료 (10/6)

VM 테스트 3개 추가(순번 빠진 노선, 대체 이유별 문구, 현위치 성공 시 문구 없음). 전체 테스트 199개, analyze 0.

**4-1. 확인 화면이 탑승 정류장을 "배열 위치"로 찾음**

- 위치: `favorite_setting_view_model.dart` `_fetchStations` — `stations[staOrder - 1]`
- 정류장 순번(stationSeq)이 1부터 빠짐없이 이어진다고 가정한다. 상세 화면 타임라인은 같은 일을 `stationSeq == staOrder` 값 비교로 한다.
- 어긋나는 노선이 있으면: 다른 정류장 이름으로 저장되고, 저장되는 staOrder 도 그 정류장의 순번이 되어 리스트·상세가 계속 "운행 없음"으로 보인다. 실제로 어긋난 노선은 확인하지 못했다.
- 수정안: 값 비교(`indexWhere`)로 찾는다. VM 테스트 1개.

**4-2. GPS 가 꺼져 있거나 위치를 못 잡아도 "위치 권한이 없어" 문구가 뜸**

- 위치: `station_setting_screen.dart` 안내 문구
- 권한은 허용했는데 GPS 만 꺼진 사용자에게 틀린 안내다.
- 수정(유저 지시로 원래 안보다 확장): 이유를 셋으로 나눠 문구를 다르게 한다. `StationSettingViewModel.fallbackReason` / `fallbackMessage`
  - 권한 거부: "위치 권한이 없어 기본 위치를 표시합니다"
  - GPS 꺼짐: "위치(GPS)를 켜주세요. 지금은 기본 위치를 표시합니다" — 권한 확인 뒤 `isLocationServiceEnabled()` 로 판정
  - 그 외(시간 초과·마지막 위치 없음): "현재 위치를 찾지 못해 기본 위치를 표시합니다"
  - GPS 를 켠 뒤에는 지도의 네이버 현위치 버튼으로 이동할 수 있다(실기기 확인 필요).

### 넘겨도 되는 것

- 확인 화면 저장 중 저장소 쓰기가 예외를 던지면 `_isSaving` 이 true 로 남아 버튼이 계속 비활성 (9/14 이월). SharedPreferences 쓰기 실패는 거의 없음.
- `main()` 초기화 실패 시 흰 화면 (9/14 이월) → 5번에서 판단.

### 이상 없음

- 단계 전환·뒤로가기: 최초 온보딩(웰컴에서 앱 종료)과 노선 추가 플로우(정류장 단계에서 리스트로 pop) 구분, 저장 후 push 진입이면 pop 으로 돌아가 리스트 reload.
- 단계 VM 을 온보딩 전체 수명으로 둬서 뒤로 갔다 와도 GPS·검색·노선 목록을 다시 받지 않음. 늦게 온 다른 정류장 응답 버림. 정류장이 바뀌면 체크한 노선 초기화.
- 지도: 10초 타임아웃·인증 실패 → 재시도 안내, GPS 8초 제한 후 마지막 위치 → 수원역 폴백.
- 스플래시: 저장 데이터 유무로 분기, 대기 중 화면이 사라지면 라우팅 안 함.

## 5. 앱 공통·빌드 설정

### 꼭 고칠 것

### 고치면 좋은 것 (작은 수정) — 수정 완료 (10/6)

**5-1. 알림 채널 초기화가 실패하면 앱이 아예 안 뜸 (흰 화면)**

- 위치: `main.dart` `await initBusNotifications();` (9/14 이월 "main() await 실패 시 흰 화면")
- `runApp` 전에 try/catch 없이 기다린다. 이게 예외를 던지면 도착 알림 하나 때문에 앱 전체가 시작되지 않는다. 네이버 지도 초기화(`NaverMapService.init`)는 이미 안에서 잡고 있다.
- 수정안: try/catch 로 감싸 실패는 로그만 남기고 앱은 띄운다. 알림을 켤 때 권한·채널 확인이 다시 돌기 때문에 기능 쪽 안전장치는 이미 있다.
- `SharedPreferencesWithCache.create` 실패는 저장소 자체가 안 되는 상황이라 화면을 띄워도 쓸 수 없으므로 그대로 둔다.

### 넘겨도 되는 것

- Kotlin Gradle Plugin 경고(flutter_naver_map 이 KGP 를 직접 적용). 지금은 빌드되지만 이후 Flutter 버전에서 실패 예정이라고 경고한다. Flutter 를 올릴 때 flutter_naver_map 도 같이 올리면서 확인.
- `flutter pub get` 에서 57개 패키지가 제약 밖 새 버전 있음. 지금 올릴 이유 없음, 기능 작업 때 필요한 것만.
- dev 의 pubspec 버전은 0.0.13+13 그대로(main 은 1.0.0+14). 출시 절차상 버전은 main 에서만 올리므로 맞다. 다음 버전 코드는 15 이상.

### 이상 없음

- 매니페스트: 권한(인터넷·위치·포그라운드 서비스 dataSync·알림), 광고 ID 제거, 서비스 선언·고정 알림 아이콘 meta-data.
- 빌드: compileSdk·targetSdk 36(Play 요구 충족), 릴리즈 서명은 key.properties, R8 기본 켜짐.
- 릴리즈에서 debugPrint 무력화, PrettyDioLogger 는 디버그에서만.
- 라우터: 상세 진입 idx 파싱 실패 시 -1 → VM 이 에러 화면.
- MainActivity 알림 설정 열기(Android 7 분기 포함).
